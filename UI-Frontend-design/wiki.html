Agent Memory Model

Agent 如何在工作过程中保留与唤起上下文。涵盖短上下文窗口、长上下文检索、外部记忆与多模态记忆。

tags:[memory, context, retrieval, long-context]
aliases:[Memory, Agent Memory, Context Retention]
created:2026-05-12
updated:2026-06-19
schema_version:3
sources:[anthropic-memory-paper, openai-cookbook-memory]

Agent Memory 指代理在执行任务过程中保留、组织和唤起信息的能力。与一次性的 LLM 调用不同，Agent 需要在多轮交互、长时间任务和跨会话场景下保持对上下文的连贯理解1。 本质上，所有 Agent Memory 都在回答同一个问题："我之前见过什么？哪些需要被记住？"

主流实现可分为四类：短上下文窗口、 长上下文检索、 外部记忆系统、 以及多模态记忆2。它们并非互斥，而是常被组合使用。

四类记忆模型

下表对比了主流 Agent Memory 实现的特征、典型容量与适用场景。

类型典型容量读写延迟适用场景
短上下文窗口8K – 32K tokens0单轮任务、即时响应
长上下文检索128K – 1M tokens低多文档分析、长任务
外部记忆系统无界中跨会话、长期项目
多模态记忆视实现中–高视觉 / 音频任务

短上下文窗口

最直接的形式：把最近的对话或文档内容完整保留在模型上下文窗口中。 Anthropic Claude 4.x 系列与 OpenAI GPT 4.x 系列均提供 128K–200K 的窗口。 优点是无须外部组件；缺点是成本随长度线性上升，且超出窗口的内容会被截断。

对单次任务而言，短上下文窗口通常足够；问题出现在跨会话或长流程中。

长上下文检索（RAG）

把资料持久化到向量数据库或文档存储，每次提问时检索相关片段注入上下文。 这是 Retrieval Augmented Generation 的核心思路3。 与之相对的 LLM Wiki 模式不依赖即时检索，而是预先把资料编译成结构化页面。

权衡

  • 覆盖广度：RAG 可覆盖百万级文档，但每次只能"瞥见"若干片段。
  • 结构化程度：Wiki 模型把资料整理成稳定结构，但需要预先编译成本。
  • 可维护性：结构化内容更易 Lint、对比、合并；RAG 索引则更难审计。

外部记忆系统

复杂 Agent（如 Plan-and-Execute 架构）通常配备独立记忆模块： 存储中间结果、目标栈、工具调用历史。代表性实现包括 MemGPT、LangGraph State、Letta 等。 

# 伪代码示例
class AgentMemory:
    def __init__(self):
        self.episodes = []     # 事件流
        self.goals = Stack()   # 目标栈
        self.skills = KV()     # 已掌握工具/技能

    def observe(self, event):
        self.episodes.append(event)
        if event.has_skill:
            self.skills[event.name] = event.handler

这类系统的核心挑战是 遗忘策略：保留过多会污染上下文；保留过少则丢失关键决策依据。 参见 Reflection 模式了解如何用自我反思维护记忆质量。

多模态记忆

视觉与音频模态需要专门的编码器。常见做法是把图像 / 音频嵌入到与文本相同的高维空间， 以便统一检索。具体细节参见 Multimodal Fusion。
