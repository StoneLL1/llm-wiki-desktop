`npm run lint` scans `UI-Frontend-design/assets/app.js` when the open-design reference folder is present - ESLint only ignored build and dependency folders, so reference prototype JavaScript was treated as source code - Keep `UI-Frontend-design` in `eslint.config.js` ignores unless the design folder is converted into app source.
`cargo generate-lockfile --manifest-path src-tauri/Cargo.toml -vv` also times out with no output — Cargo hangs before producing a lockfile, so the blocker is dependency resolution or registry access rather than a specific Rust test — Use `cargo metadata --no-deps` and `cargo fmt --check` for lightweight validation, stop residual cargo processes, and do not treat full Rust tests as passed until dependency resolution is fixed.
`cargo test --manifest-path src-tauri/Cargo.toml` times out with no output and can leave cargo processes running — Rust test execution hangs in this environment before returning diagnostics; exact toolchain cause still needs investigation — When running Rust verification, use an explicit timeout, inspect `cargo` / `rustc` / `rustup` processes after timeout, stop leftovers, and report timeout separately from pass/fail.
