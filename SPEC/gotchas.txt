# 踩坑清单 (gotchas.txt)

An EngineResult continuation was executed before the base result paths were validated — The continuation code trusted markdownPath early and could read or overwrite outside staging — Validate the complete base result before any continuation, reject pack-authored privileged continuations, and validate again after composition.

Restricting yt-dlp flags did not restrict its sockets — yt-dlp still performed its own DNS resolution and redirect traversal outside the Rust SSRF ledger — Parse the already Rust-fetched Bilibili embedded state offline; keep yt-dlp disabled until a Rust network broker can mediate every connection.

An authenticated browser profile was keyed only by item ID — Connector sessions could be replayed across projects or import sessions with the same platform — Bind and atomically consume profiles by project, import session, item, exact target hash, and platform.

Bilibili audio was accepted as M4A without proving decoder support — whisper.cpp 1.8.3 requires the optional WHISPER_FFMPEG build for that container — Require signed runtime build features, audited LGPL components, and a real Bilibili M4A qualification fixture before registration.

Temporary media and ASR outputs used loose files and fixed names — Crashes left large media behind and later retries hit EEXIST — Put every fetch/ASR attempt in a request-scoped TemporaryMediaWorkspace and reconcile runtime-temp on restart.

Visible account/avatar DOM was treated as login proof — Public article pages and logged-out headers can render those same elements — Require a known platform authentication cookie scoped to the target domain; DOM absence/presence alone never changes connector auth state.

Validating a browser subresource hostname with Node DNS did not pin Chromium's later connection — Chromium performed an independent lookup after the public-answer check, leaving an allowed CDN host open to DNS rebinding — Permit only the initial host, map it to one address from an all-public DNS set before launch, and localize cross-host assets through the Rust pinned fetcher.

Signing only a capability entrypoint or archive did not authenticate mutable installed siblings — JavaScript policies, dependencies, and helper binary digests can live outside the entrypoint while still controlling execution — Sign a sorted per-file path/size/SHA-256 inventory, reject missing/unexpected/symlink files, and reverify the whole runtime immediately before every spawn.

Node smoke scripts named `*.test.mjs` are collected by Vitest even when they use `node:test` or top-level assertions — Vitest reports “No test suite found” after the standalone assertions pass — Name manual scripts `*.smoke.mjs` and keep Node test-runner files outside the Vitest `*.test.*` pattern.

Bilibili “ASR available” was mistaken for “ASR authorized” — Capability presence alone does not grant permission to download or process temporary media, and a metadata-only success suppresses all fallbacks — Model availability and per-item user authorization separately, fail closed when subtitles are absent, and never claim ASR completion without the signed media runtime and cleanup chain.

Copying only a verified capability entrypoint broke its runtime layout — Pack launchers may import sibling modules or load adjacent DLLs/resources, while a path-level hash check still has a narrow check-to-spawn race — Preserve the signed pack directory layout; release packaging must enforce an immutable install root and platform handle-bound execution, and process groups/trees must still be terminated unconditionally.

Capability pack fallback rejected ordinary project-external imports or bypassed scan identity — Passing the original locator to a pack either violates its project/staging sandbox or reopens a scan-to-execute TOCTOU window — Revalidate the persisted source identity in Core, copy exact bytes to the item staging `authorized/` area, and expose only that snapshot plus staging-contained chained artifacts to every pack.

Same-length source or staging replacement passed length-only race checks — Path canonicalization and byte count do not establish that the opened handle is the object validated at discovery — Persist SHA-256/magic/canonical identity for sources, compare opened-vs-path file identity around staging reads, and keep deterministic validate/open swap hooks in tests.

> 记录反复出现的错误、隐蔽陷阱和"踩过一次就别再踩"的坑。

Symptom — Chat history 按 newest-first 选取后再反转为 chronological order 时，较旧消息若恰好被字符预算截断，会与下一条较新消息的 `User:` / `Assistant:` 标签粘成一行。— Root cause — 每条原始 line 自带尾随换行，但 `take_chars` 截断时会把该换行裁掉；最终直接 `push_str` selected chunks，没有额外分隔符。— How to avoid — truncated chunk 必须在原预算内保留分隔：用最后一个已预算字符替换为 `\n`，不要额外追加导致超预算；测试要让 newest 完整、older partial，并同时断言 chronological order、角色前换行和总 history chars 不超 budget。

Symptom — Import 错误提示测试在 `App.test.tsx` 单文件中通过，却在全套 Vitest 中反复抓到 lazy `Loading…` status 或等不到业务错误。 — Root cause — 测试用通用 `findByRole("status")` 与懒加载 status 竞争，同时 `mockRejectedValueOnce` 把失败绑定到“下一次任意 invoke”，全套并发/后台调用可能先消费该 rejection。 — How to avoid — 先等待懒加载后的业务输入，按具体 command（如 `preview_import`）配置 mock，并等待具体错误文本，不用通用 status 角色或全局 next-call 时序表达业务断言。

[2026-07-10] 现象 — projectId + rootPath guard 能阻止跨项目覆盖，但同一项目连续触发 capability/Import preview 时，较旧请求仍可能晚到并覆盖较新结果。— 根因 — project key 只标识作用域，不标识该作用域内的请求代次。— 规避做法 — 对可并发且“latest wins”的请求同时捕获单调 request epoch；提交结果、清 loading/error、打开 drawer 或 toast 前同时校验 project key 与 epoch。

[2026-07-10] 现象 — `WorkspaceRouter` lazy-reject 测试单文件运行通过，但完整 Vitest 套件中偶发渲染先前成功的 AgentView mock，导致找不到 `role="alert"`。— 根因 — 同一测试模块先用 `vi.doMock` 加载成功 lazy module，再以 `resetModules + doMock` 改成 reject；React.lazy 与 Vite worker 的模块 Promise 缓存使第二次定义依赖测试顺序，定向运行掩盖了不稳定性。— 规避做法 — lazy import reject 场景放到独立测试文件，顶层固定一个会 throw/reject 的模块 mock；不要在同一模块内重复定义已被 React.lazy 缓存的 chunk。必须用完整 `npm run test` 验证模块隔离测试。

[2026-07-10] 现象 — 新增 hook/controller 的 Vitest 全绿，但 `npm run build` 在测试文件报 `Mock<Procedure | Constructable>` 不能赋给具体 async callback，或字面量 props 不能从 dashboard 切到 import。— 根因 — `let mock: ReturnType<typeof vi.fn>` 会丢掉可调用签名并保留“函数或构造器”宽联合；`renderHook` 的 initialProps 又会把字符串推断成单一字面量。Vitest 运行时转译不暴露这些问题，`tsc -b` 才会失败。— 规避做法 — 跨赋值/传入 typed store 的 mock 使用 `ReturnType<typeof vi.fn<(args) => Promise<Result>>>` 或 typed async wrapper；会 rerender 的 props 显式标注 union（如 `AppView`）；完成新增测试后必须跑 build，不能以 Vitest 绿色代替类型构建。

[2026-07-10] 现象 — 用字符串 `StartsWith(repoPath)` 判断仓库外备份目录时，名称带有仓库目录前缀的 sibling path 被误判为仓库内路径。— 根因 — 路径边界缺少目录分隔符，`llm-wiki-desktop-runtime-backup-*` 也会匹配 `llm-wiki-desktop` 前缀。— 规避做法 — 先规范化路径，再用 `repoPath.TrimEnd('\\') + '\\'` 作为目录边界前缀，或使用 `Path.GetRelativePath` 验证目标不以 `..` 开头。

[2026-07-09] 现象 — Pressing Escape on a nested modal also dismissed the dialog beneath it. — 根因 — Each `useModalDialog` instance attaches its own `keydown` listener on `document`; `preventDefault` does not stop sibling document listeners, so every open modal's Escape handler fires. — 规避做法 — In a document-level Escape handler, only react if the dialog is the topmost (last `[aria-modal="true"]` in DOM order); otherwise return early and let the topmost handle it.

[2026-07-07] 现象 — 给 ensurePageSession 加了 pageSessionEpoch 守卫（每次 await 后检查 superseded 就 return null），审查仍发现快速切页时 A 页会话会闪到 B 页上。— 根因 — ensurePageSession 复用了公共方法 selectSession / createSession，而 selectSession 内部"进入时同步 set activeSessionId + await load 后再 set activeSession"，两处 set 都不认识 epoch；被 supersede 的调用者虽然自己 return null，但子调用 selectSession 已经把 A 的会话 set 上去了。createSession 内部也调 selectSession，同样的泄漏。epoch 守卫只挡了 ensurePageSession 自己的 await 边界，挡不住它委托出去的复合方法。— 规避做法 — 一个方法若需要"被 supersede 时完全不改变 store"，就不能复用会改状态的公共方法（selectSession/createSession），必须自己内联 invoke（load_chat_session / create_chat_session）并在每次 await 后、set 提交前重新校验 epoch/current。即"原子提交只能由持有守卫的那一层做，不能再下放"。写这类守卫前先问"我调的子函数会不会在我看不见的地方 set 状态"。

[2026-07-07] 现象 — loadSessions 的 "activeSessionId 为空就自动选最新一条" 副作用，会在 ensurePageSession 的竞态窗口里抢跑：A 页 ensurePageSession 正 await list，B 页切过来把 activeSessionId 清空，A 的 list resolve 后 loadSessions 见 activeSessionId 为空就自动选了最新（可能是 A 页的会话），赶在 ensurePageSession 的 epoch 检查之前把 A 会话选上。— 根因 — loadSessions 的 auto-select 是无条件副作用，ensurePageSession 调它只是为了刷 sessions 列表再自己搜，并不想要这个副作用，而副作用发生在 epoch 检查能拦住之前。— 规避做法 — 复合操作里"只想刷新数据、不想要某副作用"时，给被调方法加显式 opt-out（这里 loadSessions 加 `{ autoSelect?: boolean }`，默认 true 保持旧行为，ensurePageSession 传 false）。不要指望在上层用守卫拦住下游的副作用——时序上拦不住。

[2026-07-06] 现象 — Batch 4 wiki index 之后，`SearchService::read_page`（单文件，走 `FileStore::file_hash` 重读新鲜 bytes 算 hash）与 `SearchService::scan_wiki`（走索引缓存 hash）在**同一 mtime + 同一 size 但内容已变**的极端场景下可能返回不同 hash；graph cache 用 `page.hash` 算 content_hash，理论上可能在该场景下命中/未命中行为与改前不一致。— 根因 — 索引的失效判定是 mtime+size（PERF-004 的核心就是不再为每个文件每次重算 hash，否则 fs.read 省不下来）；某些文件系统/编辑器组合（如 `touch -d` 同秒写回等长内容、或带纳秒截断的挂载）能让 mtime+size 不动而内容变。— 规避做法 — 这是 plan 明确接受的"mtime/size/hash"风险包络（hash 作为派生字段存储，不作为每次重算触发器）。若用户报"改了文件图谱没刷新"或"save 报 hash mismatch 但扫描没看出变化"，先怀疑此场景：让用户再改一次（推进 mtime）或显式 `build_graph` 强制重建。未来若要消除该窗口，可在 `save_page` 后主动 `index.evict` 当前项目（save 路径已知文件变了），但 read_page 与 scan_wiki 在并发外部编辑下的窗口仍需 hash-fallback 才能完全闭合，超出 Batch 4 MVP 范围。

[2026-06-22] 现象 — 导入预览显示提取成功，但 compile 看不到内容；改成 `.md` 后，取消过的 preview 又会悄悄进入 compile。 — 根因 — 提取器原先写 `raw/extracted/*.txt`，而 compile 只枚举 Markdown；若直接把预览产物改成 `.md` 并枚举整个目录，又会把未确认孤儿产物当正式输入。 — 规避做法 — 成功提取统一写 `.md`，compile 仅从 `.app/source-index.json` 枚举已确认 source 的非空 Markdown并只复制这些文件到 workspace；预览写入采用 create-new/内容一致复用，绝不覆盖外部编辑。

[2026-06-22] 现象 — 单个 ZIP entry 有 64 MiB 检查，恶意 Office 文件仍可在检查前或通过大量小 entry 造成 OOM；超大 XLSX 列引用还能触发巨量 `row.resize`。 — 根因 — 先 `fs::read` 整个 OOXML 容器，且没有容器大小、entry 数、累计展开大小和 Excel 列上限。 — 规避做法 — 所有导入源先做 64 MiB metadata 上限；OOXML 用 `File` 流式打开，限制 4096 entries、累计展开 64 MiB；XLSX 列限制到 XFD/16384，坏 shared-string 索引直接失败而不是静默丢值。

[现象] `slice.iter().take_while(pred).rev().find(...)` 编译报 `the trait DoubleEndedIterator is not implemented for TakeWhile<...>`。
[根因] `TakeWhile` 不是 `DoubleEndedIterator`（无法从尾部反向，因为要从前缀判断），所以 `.rev()` 在它上面非法。`.iter().rev().take_while()` 顺序也不对（语义变了）。
[规避做法] 要在「截至某元素的切片」里反查最近一项：先 `let v: Vec<&T> = iter.take_while(pred).collect();` 再 `v.iter().rev().find(...)`。chat 的 save_answer_to_wiki 找「消息 id 之前最近的 user 轮」就是这个模式。
