# 踩坑清单 (gotchas.txt)

> 记录反复出现的错误、隐蔽陷阱和"踩过一次就别再踩"的坑。
> 每条记录：现象 — 根因 — 规避做法。遇到同类问题先查这里。

======================================================================
serde tagged enum `#[serde(tag="kind")]` 不 camelCase 结构变体字段 — `rename_all` 作用在 enum 的变体名上，不会渗透到 struct-variant 内部字段，导致嵌套 `pending_action` 等字段以 snake_case 外泄，前端 TS 类型对不上 — 改用「struct + `kind` 鉴别字段」结构体，并在 struct 上单独加 `#[serde(rename_all="camelCase")]`，避免在 enum 上依赖 rename_all 渗透。
`Err(...).with_details(...)` 闭包缺右括号导致 "mismatched closing delimiter" — 写多行 `return Err(BackendError::new(...).with_details(...));` 时容易漏掉最外层 `Err(` 的闭合 `)`，rustc 报「unclosed delimiter / mismatched closing delimiter」且行号指向文件末尾 — 计数好 `Err(` 的层数，`}));` 不够就补成 `})))`。
`include_str!` 模板路径在 Windows 上以 `CARGO_MANIFEST_DIR` 为基准 — 模板必须放在 `src-tauri/templates/...` 并用 `../../templates/...` 相对路径，移动目录时要同步改 include 路径，否则编译期报文件找不到。
提取 HTML 标题时切片索引偏移错误 — `extract_html_title` 用 lowercased 字符串定位 `<title>` 后，原字符串的索引偏移需要逐字精确计算：`after_tag` 包含 `>` 时，`content_start` 已跳过 `>`，但后续搜索 `</title>` 的 `tag_rest` 仍以 `>` 开头，导致 `end` 多计 1 个字符，标题末尾附带 `<` — 跳过 `>` 后再搜索 `</title>`，保证 content 切片不包含标签字符。包含属性的标题 (`<title lang="en">`) 同理需要在 `after_tag.find('>')` 后 +1 跳过 `>`。

`cargo test` 默认联网解析依赖在本机超时 — 依赖已缓存时加 `--offline` 即可跑通全套测试；不要把「联网超时」误判成「代码失败」。
======================================================================
`npm run lint` scans `UI-Frontend-design/assets/app.js` when the open-design reference folder is present - ESLint only ignored build and dependency folders, so reference prototype JavaScript was treated as source code - Keep `UI-Frontend-design` in `eslint.config.js` ignores unless the design folder is converted into app source.
`cargo generate-lockfile --manifest-path src-tauri/Cargo.toml -vv` also times out with no output — Cargo hangs before producing a lockfile, so the blocker is dependency resolution or registry access rather than a specific Rust test — Use `cargo metadata --no-deps` and `cargo fmt --check` for lightweight validation, stop residual cargo processes, and do not treat full Rust tests as passed until dependency resolution is fixed.
`cargo test --manifest-path src-tauri/Cargo.toml` times out with no output and can leave cargo processes running — Rust test execution hangs in this environment before returning diagnostics; exact toolchain cause still needs investigation — When running Rust verification, use an explicit timeout, inspect `cargo` / `rustc` / `rustup` processes after timeout, stop leftovers, and report timeout separately from pass/fail.
Tauri v2 单元测试二进制在本机启动即崩 (exit code 0xc0000139, STATUS_ENTRYPOINT_NOT_FOUND) — `cargo test` 编译出的 test 可执行文件需要 WebView2 运行时相关 DLL，而当前 Windows 测试环境缺少这些入口点，导致测试二进制加载阶段就失败（代码本身编译通过） — 在本机只能用 `cargo build` + `cargo check` + `cargo clippy` 验证 Rust 代码正确性；真正的 `cargo test` 执行需要放到有完整 WebView2 运行时或 CI 环境。新增 Rust 单测时仍要写，但不能依赖本地 `cargo test` 验证。
`tauri-plugin-notification` 的 `NotificationBuilder::new()` 是私有 (private) 的 — 不能直接 `NotificationBuilder::new(title)` — 必须通过 `NotificationExt` trait：`app_handle.notification().builder().title(...).body(...).show()`，且 `.show()` 返回 `Result<(), Error>`（不是 Future，不能 `.await`）。
======================================================================
`#[derive(Default)]` 与手写 `impl Default` 不能共存 — 当某个字段类型（如 `NotificationService`）无法 derive Default 时，需要对整个 struct 手写 `impl Default`，此时必须删除 struct 上的 `#[derive(Default)]`，否则报 E0119 conflicting implementations。
`tauri::tray::TrayIconBuilder::menu_on_left_click` 在 Tauri 2.9+ 已 deprecated — 改用 `show_menu_on_left_click`。
